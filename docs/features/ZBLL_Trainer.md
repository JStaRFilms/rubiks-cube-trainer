# ZBLL practice

B11 implements the resumed family, subset and manual case practice brief. The accepted B10 collection is unchanged. This is individual practice, with no ZBLL set or run system.

## Physical flow

Confirm a fully solved cube aligned to its centers and held with the displayed down/front colors before every setup. Apply the sourced canonical setup, then recognize and solve the last layer. F2L stays solved and LL edges start oriented. An arbitrary oriented LL permutation is not a valid base. Next, retry, reload and interrupted work require a fresh base confirmation. Timer completion is self-reported.

Frozen guidance returns any net proper regrip to the held frame before its required final AUF. Review includes that AUF. When using another unobserved algorithm, solve and align the physical cube rather than blindly applying the guide's AUF.

## Client, worker and store

ZBLLPractice follows F2L's base-confirmation and cancellable request lifecycle. ZBLLClient correlates request ID, worker instance, epoch, frame, selection and actual angle, then independently checks the exact frozen guidance. ZBLL worker's readiness operation initializes and validates the actual 493-case collection. Practice and save operations prove the requested challenge's sourced setup, identity, context and complete guidance instead of revalidating every unrelated case per repetition. Generation suspends before timing or player work. Post-await checks compare settings, session, restore epoch, worker ownership and the full global algorithm list.

Settings select actual manifest families, sourced COLL groups or individual canonical IDs. Ordered cycling and shuffled cycles are individual drills, not a persistent run. A transient shuffle visits each selected case once before reshuffling; settings/session/restore changes reset that order. Fixed/random pre-U and yaw, execution/recognition and shared inspection settings persist on this device. Empty selections cannot save or start.

Confirmed base -> frozen selection and global guidance read -> filtered 493-member payload -> real model initialization -> validated setup/identity/context/goal -> correspondence and post-read checks -> immutable DOM presentation -> shared TimerController -> semantic validation -> acknowledged Repository transaction -> saved history and review.

Recognition renders no generated case/family/subset/source identity, algorithm or explanatory hints before intentional stop. Interrupted recognition stays hidden until deliberate Review. Running hides preparation guidance. Selection controls describe the pool, not the generated case. Keyboard/native-control ownership, save retry, emergency export, interruption and update protection remain shared timer behavior.

## Identity, versions and personal guidance

All 493 accepted canonical memberships appear once. Families T/U/L/Pi/S/AS have 72 each, H has 40, PLL has 21. Forty non-PLL COLL groups and three PLL groups come directly from manifest membership. Source labels and reference aliases are lookup information, not universal numbering or extra cases.

Challenge versions identify collection `zbll-library-v1`. A strict case proof also retains canonical entry dataset and identity policy, plus actual manifest family/subset/source/reference labels. Shared PLL cases retain `pll:speeden-v1:*`, `cfop-libraries-v1` and their existing PLL policy. New entries retain `zbll-ll-pre-u-yaw-v1`. Personal guidance changes neither canonical setup nor identity. Stored alias override keys reject; the ZBLL editor's PLL membership edits the existing canonical PLL key seen by Time Attack.

Repository validates the complete proposed global override list before revision-checked save/reset. F2L generation still receives F2L records only. OLL/PLL run generation validates the global list, then receives only its real inventory's records. ZBLL receives exactly its 493 members. Ownership comparisons use the full list. Historical guidance never changes after an edit or reset.

## Schema and statistics

Database and export versions remain 1. Optional `zbllPractice` preferences decode exact fields and canonical nonempty unique membership. ZBLL goal options require the frozen selection/policy snapshot. ZBLL proof metadata requires collection-compatible canonical versions and actual manifest membership. Strict validators reject unknown fields, versions, goals, timing and forged context even after warm proof caches. Cross+2 and ZBLL sets/runs remain closed. Old mixed backups, attempts and linked LL reconciliation remain supported.

History reuses penalty/delete/latest Undo, sessions, backup and storage errors. ZBLL statistics scope to actual saved session attempts. Coverage counts distinct canonical IDs against the 493 available collection and the declared pool, including DNF and interrupted attempts. Family/subset/case summaries show counts and failures. Times and preparation metrics group by conservative compatible configuration keys including mode, inspection, frame, declared selection/policies, actual angles, canonical metadata and frozen guidance. Heterogeneous groups do not get pooled rankings or mastery claims. Completed DNF contributes preparation, not successful execution; interruptions have incomplete preparation and no successful time.

## Offline and verification

Initial readiness initializes the real ZBLL worker/library before the trainer is opened. An engine-local bounded cache reuses successful ZBLL identity calculations keyed by actual state bytes. It does not trust imported identity strings or skip structural, legal-state or goal checks. The release manifest precaches all emitted workers/model/player/library assets and exact source notices. Cache-only recheck, repair and safe updates preserve personal data. Build, browser and alternate-release tests run serially; normal dist is restored afterward.

Actual checks, initial failures, bundle hashes and unrun limits belong in `docs/audits/ZBLL_Trainer_Integration.md` and its bundle evidence. Emulation does not certify physical phones, installed PWAs, screen readers, audio, GPU or solve latency. Parent owns acceptance and Q04.
