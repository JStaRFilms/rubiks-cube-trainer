# FR-001: Offline app and safe updates

## User story

As a trainer user, I want an installable app that works offline after setup, including features I have not opened yet.

## Proposed flow

Complete setup of required assets and caches, report readiness only after verification, support interrupted setup recovery, and offer updates without reloading an active attempt.

## Technical considerations

Follow [PLAN.md §§2, 7](../imports/PLAN.md). Cache all included assets, including the 3D player, before declaring offline readiness. `navigator.onLine` alone is not proof. Keep asset/engine versions consistent. Planned worker and asset implementation is not yet present or verified.

## Dependencies

B01/B02 are planned implementation tasks; trainer increments and Q06 verify coverage. Setup/cache decisions belong to G02. No application artifacts are claimed present.

## Acceptance criteria

- After setup, cold offline navigation and installed restart load every included trainer and 3D review, including a feature never opened online.
- Interrupted setup resumes or retries without claiming readiness prematurely.
- An update cannot interrupt an active attempt; history survives update.
- Offline checks report actual browser/device versions and results.
