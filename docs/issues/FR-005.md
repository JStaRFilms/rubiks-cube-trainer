# FR-005: Backup, restore and storage integrity

## User story
Keep personal records recoverable and receive honest errors when local storage fails.

## Proposed flow
Export settings, sessions, attempts, algorithms and sets/runs, excluding rebuildable caches. Validate an entire import before confirmed replace. Offer backup before replacement and explain browser-storage limits.

## Technical considerations
Follow [PLAN.md §6.4](../imports/PLAN.md). Keep IndexedDB migration version distinct from export format version. Invalid imports leave existing data intact. Cache deletion must not delete personal history.

## Dependencies
G02 schema/format decisions, B01 implementation and Q01/Q06 verification are planned. FR-004 record definitions apply.

## Acceptance criteria
- Round-trip preserves supported user data.
- Malformed or unsupported newer files leave existing data unchanged with actionable feedback.
- Migration fixtures pass; restore and clear require confirmation.
- Quota/write failure never shows a false saved state.
