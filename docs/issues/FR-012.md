# FR-012: Verified case data and personal algorithms

## User story
Use stable case identities and personal algorithms without mistaking valid notation for a solution to the selected case.

## Proposed flow
Keep canonical IDs/states independent of overrides; record sources and dataset version. Validate notation, intended identity and solving behavior. Validate imports before storage; reset removes an override.

## Technical considerations
Follow [PLAN.md §§6.3, 4.3–4.5](../imports/PLAN.md). Define AUF/rotation equivalence. Check license and attribution before reuse. An algorithm that solves some state is not necessarily correct for the requested case.

## Dependencies
G02 conventions, B07/B10 data and trainer checks are planned. Applies to FR-008–010.

## Acceptance criteria
- Fixtures verify declared coverage and detect duplicates.
- Every bundled setup meets trainer constraints and its algorithm solves the intended case.
- Wrong-case/invalid overrides and imports are rejected without changing existing data.
- Reset restores canonical default; equivalence policy is explicit.
