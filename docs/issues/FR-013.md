# FR-013: All-level accessible controls

## User story
Understand each trainer's goal, difficulty, setup/reset and review, and use it on phone or desktop.

## Proposed flow
Use phone-first layouts for modern iPhone/Android browsers and responsive desktop keyboard controls. Keep primary actions reachable; explain terminology and provide focus, contrast, reduced motion and usable touch targets.

## Technical considerations
Follow [PLAN.md §§2, 3.1](../imports/PLAN.md). Do not depend on one phone model or use cube colors as the only state label. Player, settings and history inputs must not trigger timer actions.

## Dependencies
D01 interaction design, trainer screens and Q06 verification are planned. Requires shared timer/player contracts FR-002/003.

## Acceptance criteria
- Core flows are keyboard navigable with visible focus; touch targets and contrast meet documented criteria.
- Reduced motion retains text review; non-color cues identify states.
- Player/settings/history actions cannot start or stop timer.
- Verify current iOS Safari, Android Chrome and desktop Chromium/Firefox with versions recorded; desktop Safari where available.
