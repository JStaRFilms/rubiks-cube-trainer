# FR-016: Later account and synchronization

## User story
Eventually sync settings, history, algorithms and sets across devices without losing offline changes or user data.

## Proposed flow
After local records, backup and migrations stabilize, define provider, cost and privacy with owner approval. Resolve offline writes, conflicts, deletion, duplicate attempts, authentication failures, export and account removal before implementation.

## Technical considerations
Follow [PLAN.md §9.2](../imports/PLAN.md). Do not add an initial backend or speculative sync fields. File backup remains useful if sync is later added.

## Dependencies
S01 is planned after Q03; provider/privacy/cost approval must precede implementation. No account or backend artifact is claimed present.

## Acceptance criteria
- Approved architecture records provider, privacy/cost terms and conflict/data-loss behavior.
- Before exposure, tests cover concurrent edits, offline writes, deletion/export and authentication failure.
- No backend/account is introduced before approval; local export remains available.
