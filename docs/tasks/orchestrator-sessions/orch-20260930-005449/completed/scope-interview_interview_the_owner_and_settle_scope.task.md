# Scope interview

## Objective

Reach shared understanding of the project before accepting inherited ideas as requirements.

## Scope

Ask about audience, first useful training session, video reconstruction ambition, and existing code. Follow with dependent decisions about training behavior, devices, offline guarantees, data recovery, case sourcing, solver guarantees, collaboration, and delivery constraints. Recommend scope and challenge unsupported assumptions.

## Definition of done

Every build-critical decision is answered or deferred. Required features, experiments, exclusions, and later ideas are distinguishable. The owner has reviewed the resulting scope.

## Expected artifacts

An agreed scope summary in the conversation. The later plan-authoring task records those decisions in project documents.

## Boundary

Do not implement or assume answers. Unknown speaker attribution stays unknown.
